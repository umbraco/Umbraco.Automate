# Upgrade to Umbraco 19

From `18.1.0` to `19.0.0-beta1` (tag `release-19.0.0-beta1`), refreshed to `19.0.0-rc1`.
Branch `v19/dev`, cut from `v18/dev`. The rc1 refresh is on `v19/feature/cms-19-rc1`, cut from
`v19/dev` at d80df6db.

**Targets CMS release:** `release-19.0.0-rc1` (was `release-19.0.0-beta1`). This is a
pre-release, so all three products ship as pre-releases too: `19.0.0-rc1` (they shipped as
`19.0.0-beta` on beta1, following the `18.0.0-beta` naming used for v18).

## Breaking changes for consumers

- .NET 11 and CMS 19 are required.
- Removed: `NotifyEditorAction`'s constructor without an `IAutomationActionAuthorizer`;
  `AutomateOptions.Enabled`; `GovernanceOptions` and its four properties
  (`Umbraco:Automate:Governance`); `ScriptingOptions.StatementTimeout` and
  `ScriptExecutorOptions.StatementTimeout`.
- `IAutomationRunService` (`GetStepRunDataAsync`, `GetTriggerDataAsync`),
  `IAutomationActionAuthorizer` (`AuthorizeContentRootAsync`, `AuthorizeMediaRootAsync`,
  `AuthorizeContentParentAsync`, `AuthorizeMediaParentAsync`) and `IOAuthCredentialsService`
  (`GetCredentialIdsNotModifiedSinceAsync`) lose their default implementations: custom
  implementations must implement those members.
- The removed settings were already ignored, so sites that still set `Umbraco:Automate:Enabled`,
  `Umbraco:Automate:Governance:*` or `Umbraco:Automate:Scripting:StatementTimeout` see no change;
  the keys just leave the appsettings schema.
- `PublishContentAction` constructor: gains `IUserService` and `PropertyEditorCollection`
  (after `IContentPublishingService`), to warn when a named-culture publish leaves shared
  properties unpublished because the service account lacks "Allow editing shared content".
- `FindContentAction` and `FindMediaAction` constructors: `IExamineManager` and the type
  services are replaced by `ISearcherResolver` and `IEntityService` (plus `ILanguageService` for
  content).
- Find Content / Find Media now run on Umbraco Search. Behaviour against v18:
  1. Contains matches the value as one unbroken run inside the name, ignoring case and runs of
     whitespace, on words and word starts only. "press" no longer finds "Compress Archive" (#90).
  2. StartsWith: every term must start a word of the name, in any order. A term without
     punctuation may start any run of letters and digits ("world" finds "Hallo-World Page"); a
     term with punctuation must start a whitespace-separated word. A stop word now finds names
     v18 couldn't ("the" finds "The Homepage").
  3. Exact is whole-name equality ignoring case and whitespace runs. v18 was an analysed
     phrase match, so "homepage" no longer finds "The Homepage".
  4. Only the name is searched. v18 also matched the last word of a multi-word value against
     every indexed field.
  5. A name made only of `*` or `?` fails validation.
  6. A stale content or media type key matches nothing (v18 dropped it, and dropped the whole
     filter if every key was stale).
  7. With no culture set, the default language is searched. Culture codes are matched against
     the site's languages ignoring case.
  8. Trashed content and media are excluded, including for unpublished content. Protected
     content is excluded, as before.
  9. `ContentTypeKey` on content matches is now filled in. Draft searches match and return the
     draft name.
  10. Results are ordered by score. A run examines at most 2000 hits, and `LimitReached` is also
      true when that ceiling stops the search. A name made only of stop words or symbols is
      checked by scanning, so on a very large site a match past the first 2000 hits can be missed.
  11. Known limitation: words the index drops are taken from the Examine provider's default
      English analyzer. A custom analyzer or another search provider can make some names
      unfindable.
- Dropdown settings render with the single-select editor (same stored value shape).
- The Create Content, Create Media, Move Content and Move Media pickers are `[Required]`
  explicitly: an automation with an empty pick fails validation at publish, and the settings
  dialog flags it (it was already required by inference on the server).
