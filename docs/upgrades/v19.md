# Upgrade to Umbraco 19

From `18.1.0` to `19.0.0-beta1` (tag `release-19.0.0-beta1`).
Branch `v19/dev`, cut from `v18/dev`.

**Targets CMS release:** `release-19.0.0-beta1`. This is a pre-release, so all three products
ship as pre-releases too: `19.0.0-beta`, following the `18.0.0-beta` naming used for v18.

## Decisions

- 02-11-2026: Branch `v19/dev`, cut from `v18/dev`, per CONTRIBUTING.md's branch-per-major model.
- 02-11-2026: No third-party majors in this upgrade (JsonSchema.Net.Generation 7 and Cronos 0.13
  not picked).
- 02-11-2026: The v19 demo and package-test sites skip the Clean starter kit until a CMS 19
  release of Clean ships.
- 02-11-2026: Find Content / Find Media on Umbraco Search. Umbraco Search (CMS 19 core and the
  Umbraco.Cms.Search package) matches whole words and word-start prefixes only; leading
  wildcards are rejected (`release-19.0.0-beta1:src/Umbraco.Cms.Search.Provider.Examine/Services/Searcher.cs:134-140,345-350`,
  Umbraco.Cms.Search#18, `TextTests.cs:145`). Decided:
  - Contains: word-based through `ISearcher` (no longer matches inside a word, #90 case).
  - StartsWith: keeps v18's word-start meaning, which `ISearcher` does natively.
  - Exact: whole-name equality, ignoring case.
  - Protected content: excluded, as v18's External index did (`accessContext: null`, as the
    CMS's own `IndexedEntitySearchService` does; Umbraco.Cms.Search#124).
  - Trashed content and media: excluded, with the CMS's `PathIds` filter
    (`IndexedEntitySearchService.cs:117-134`).
- 03-11-2026: Automate grants no "Allow editing shared content" permission (it creates no user
  groups). Publish Content keeps a run-log warning when a named-culture publish leaves shared
  properties unpublished because the service account lacks it; the step still succeeds, since
  the culture did publish. Documented in `docs/identity-ownership-permissions.md`.
- 03-11-2026: Automate's SignalR editor-notification hub now honours the server's
  `SkipNegotiation` setting (WebSockets, no negotiate), as the CMS's own hub does at 19
  (`server-event.context.ts:111-118`) and already did at 18.1. Taken into task 5 with the token
  removal.
- 03-11-2026: Keep the new `Umbraco.Automate.Tests.CmsIntegration` project (NUnit, on
  `Umbraco.Cms.Tests.Integration`) for tests that need a real CMS database. Test-only: adds
  `Umbraco.Cms.Tests.Integration` 19.0.0-beta1 and `NUnit3TestAdapter` 5.1.0 to
  `Directory.Packages.props`, plus `VersionOverride`s in that project only
  (`Microsoft.NET.Test.Sdk` 18.11.0, which the CMS test package needs, and
  `Microsoft.CodeAnalysis.CSharp.Workspaces` / `Workspaces.Common` 5.9.0 to match the CMS).

## Breaking changes for consumers

- .NET 11 and CMS 19 are required.
- Removed: `NotifyEditorAction`'s obsolete constructor; `AutomateOptions` obsolete member at
  line 24; `GovernanceOptions` and `Umbraco:Automate:Governance`; `ScriptingOptions` and
  `ScriptExecutorOptions` obsolete members.
- `IAutomationRunService`, `IAutomationActionAuthorizer` and `IOAuthCredentialsService` lose
  their default implementations: custom implementations must implement those members.
- `PublishContentAction` constructor: gains `IUserService` and `PropertyEditorCollection`
  (after `IContentPublishingService`), to warn when a named-culture publish leaves shared
  properties unpublished because the service account lacks "Allow editing shared content".
- `FindContentAction` and `FindMediaAction` constructors: `IExamineManager` and the type
  services are replaced by `ISearcherResolver` and `IEntityService` (plus `ILanguageService` for
  content).
- Find Content / Find Media now run on Umbraco Search. Behaviour against v18:
  1. Contains matches the value as one unbroken run inside the name, ignoring case and runs of
     whitespace, on words and word starts only. "press" no longer finds "Compress Archive" (#90).
  2. StartsWith: every term must start a word of the name, in any order. A term without
     punctuation may start any run of letters and digits ("world" finds "Hallo-World Page"); a
     term with punctuation must start a whitespace-separated word. A stop word now finds names
     v18 couldn't ("the" finds "The Homepage").
  3. Exact is whole-name equality ignoring case and whitespace runs. v18 was an analysed
     phrase match, so "homepage" no longer finds "The Homepage".
  4. Only the name is searched. v18 also matched the last word of a multi-word value against
     every indexed field.
  5. A name made only of `*` or `?` fails validation.
  6. A stale content or media type key matches nothing (v18 dropped it, and dropped the whole
     filter if every key was stale).
  7. With no culture set, the default language is searched. Culture codes are matched against
     the site's languages ignoring case.
  8. Trashed content and media are excluded, including for unpublished content. Protected
     content is excluded, as before.
  9. `ContentTypeKey` on content matches is now filled in. Draft searches match and return the
     draft name.
  10. Results are ordered by score. A run examines at most 2000 hits, and `LimitReached` is also
      true when that ceiling stops the search. A name made only of stop words or symbols is
      checked by scanning, so on a very large site a match past the first 2000 hits can be missed.
  11. Known limitation: words the index drops are taken from the Examine provider's default
      English analyzer. A custom analyzer or another search provider can make some names
      unfindable.
- Dropdown settings render with the single-select editor (same stored value shape).
