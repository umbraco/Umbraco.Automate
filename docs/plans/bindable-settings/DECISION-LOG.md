- **05-10-2026 (sad-path review):** Ran the new sad-path-finder skill over this plan and PR #206. The user decided:
  - **Empty parent bindings fail.** The four optional parent fields get `BindingMustResolve`, so a binding that resolves to empty fails the step instead of silently using the root. New task T12.
  - **Only string fields get the switch.** `valueKind` becomes String / Scalar / Collection, and only `String` is wrapped, because a `${ }` string can't be deserialized into an int, Guid, enum or object.
  - **The media key picker has a per-field folder filter.** Files only by default. Move Media's `MediaKey` allows folders, because Get and Update Media Property fail on a folder.
- **05-10-2026 (sad-path review):** Recommended defaults taken, no user input needed:
  - The form routes each field once, when it loads (decision 10).
  - On switch-off, a GUID in the box wins over the remembered pick, and other text is dropped.
  - Insert binding remembers the pick, as the switch does.
  - The missing-editor fallback only applies once a field has been routed to the wrapper.
- **05-10-2026 (sad-path review), OPEN:** Old non-canonical GUIDs (upper-case, braces) may show as "not found" in CMS's picker, although the run accepts them. Not fixed by treating them as binding mode: the wrapper is generic, and other pickers (Forms) store values that aren't GUIDs. T9 captures what's shown, then decides. Normalising on the content and media fields is the likely fix.
- **05-10-2026 (sad-path review):** The review also confirmed #206 shouldn't merge as it is. It conflicts with `v18/dev` in `Constants.cs`, and it would release `Constants.EditorUiAliases` aliases that this plan drops. Closing it stays in T10, behind the human gate.
- **05-10-2026 (build):** The plan folder is committed on #443's feature branch only, not on `v18/dev` as the build skill's default would do (the user's call). It reaches `v18/dev` through #443's review.
- **05-10-2026 (build T2):** `valueKind` values are PascalCase (`"String"`), not the lower-case SPEC assumed. The Management API's `JsonStringEnumConverter` has no naming policy, and we follow the existing convention rather than special-casing this enum. SPEC, STORIES, PLAN and the acceptance spec are updated.
- **05-10-2026 (build T2):** Reviewer suggestions not taken in T2, as follow-ups: (1) `IsCollection` doesn't unwrap `Nullable<T>`, so `ImmutableArray<string>?` would be Scalar, as the Required rule already treats it, and no settings type uses one; (2) specs pinning `Dictionary` and `IEnumerable<T>` as Collection could be added; (3) `String = 0` as the default is deliberate.
- **05-10-2026 (build T12):** A dedicated internal `SettingsBindingException : InvalidOperationException`, so the existing classifier records it as a terminal ConfigurationError with no change to `ActionStepBody.cs` (which PR #441 also edits). The flag is ignored on a field without `SupportsBindings`, and isn't checked on list items. Sensitive fields show `********` instead of the raw expression. Follow-up once #441 merges: an `ActionStepBody`-level test that a flagged empty binding fails the step without running the action.
- **05-10-2026 (build T3):** The media key picker validates `mandatory` on its own host, because CMS `umb-input-media` has no `required`/`valueMissing`. The picker must work outside the bindable wrapper too, since its alias is public. An unknown `folderFilter` falls back to `filesOnly`. The C# `Constants.EditorUiAliases` class is new: #206's version was never merged. The T9 edge-case captures now cover this picker as well as the document picker.
- **05-10-2026 (build T5):** "Decide once" = a sticky set of wrapped field keys plus a snapshot of the loaded values, reset only when the form gets a new step or values from outside. A field that isn't yet wrapped is re-checked so binding sources that arrive late still wrap it, but a wrapped field is never unwrapped. The wrapper latches its switch so it doesn't vanish after switch-off. That latch moves into the form as a config entry in T6.
- **05-10-2026 (build T5), follow-ups:** (1) the webhook trigger's settings modal merges settings, so the form's echo guard never matches and the form reloads on every edit, which re-decides routing for a third-party trigger field (pre-existing); (2) the node settings modal can re-create the form when the connection list arrives, taking the edited values as "loaded" (pre-existing, a short window).
- **05-10-2026 (build T5), OPEN:** found in the smoke test: after switching on with a picked GUID carried over as text, Insert binding inserts at the caret and gives `<guid>${ trigger.contentKey }`, which can never resolve. Decision needed before T6.
- **05-10-2026 (build T5), decided:** Insert binding keeps inserting at the cursor, even when the box holds a carried-over GUID (the user's call). The author clears or edits the text first. This resolves the OPEN entry above. It won't be special-cased in T6.
- **05-10-2026 (build T6):** Remembered values live on the editor element, so a `visibleWhen` hide/show inside the open panel forgets them while the switch survives. That's accepted: it's rare, and holding them in the form isn't worth it yet. Switching on with an empty pick clears the remembered pick, so a deliberate clear isn't undone. A GUID left in the box on switch-off doesn't update the remembered pick.
- **05-10-2026 (build T7):** The six ContentKey fields use `validationLimit` min 1, matching Move Content. The schema builder's implied Required (non-nullable string) still applies on the server: a `${ }` value passes it, and a cleared picker fails it with "The Content Key field is required." Labels stay "Content Key" (Move's says "Content"; a UX tidy-up for later if wanted).
- **05-10-2026 (build T7):** Deploy.Automate isn't affected by bindable pickers. Its automation connector declares only workspace, group and connection dependencies (process pass 6), and step settings travel verbatim. `docs/engineering-spec.md:1985-1989`, which says Deploy resolves content keys, is stale; that's a docs follow-up.
- **05-10-2026 (build T8):** Correction to the folder-filter entry above: the reason given ("Get and Update Media Property fail on a folder") was wrong. The three actions work on folders. The user chose to keep files only for those fields anyway, as a deliberate narrowing: the picker offers media items, and a folder can still be reached through a binding. Trade-off accepted: an old automation pointing at a folder still shows and runs it, but once the author removes that folder they can only re-select it by binding.
- **06-10-2026 (build T9), decided by the user from the T9 edge-case captures (screenshots 10–19):**
  - Upper-case and braced GUIDs: the wrapper converts a stored GUID in any accepted format (any case, braces in pairs, surrounding spaces) to canonical lower-case before handing it to the wrapped picker, so the node or item shows. The converted value is saved on the next save. This resolves the earlier OPEN entry about non-canonical GUIDs.
  - Deleted media item: left as it is (CMS `umb-input-media` shows an empty picker). The run fails with the action's not-found message.
  - Read-only: the two read-only acceptance tests are deleted. The step settings form has no read-only mode, so STORY-2 AC9 and STORY-5 AC5 can't be reached today. The wrapper and picker still honour `readonly` for when one exists.
  - An author whose group has only the Automate section sees a picked node's name, but "Choose" lists nothing (CMS tree permissions). Accepted: they can bind instead. To be noted in SPEC.
- **06-10-2026 (build T9):** Correction to the GUID decision above: the wrapper converts for display only. The canonical form is saved once the author changes the field or switches back from a binding. An untouched field keeps its stored form, so opening an old step doesn't mark it changed. The run accepts every format, so nothing breaks.
- **06-10-2026 (build T9):** The wrapper's form-control registration: remove the inner editor in `willUpdate` (before the render that detaches it), and add it in `updated` (after it's attached). That way the validation mixin never anchors validity on a detached element. Side finding: the CMS `UmbFormControlMixin` sets `#runValidatorsCallback = () => this._runValidators` (returns the method instead of calling it), so an inner control's validity events don't update the host. This is worth an upstream Umbraco-CMS issue. The wrapper works around it with a re-check after `updateComplete`. Follow-up suggestions not done: a spec that an empty required picker in editor mode blocks Save, and moving `collectPageErrors` into AutomateUiHelper.
